# 网络配置与连接排查

本指南针对 Ubuntu 原生 Docker Engine。查看器只选择现有网卡并订阅数据，不设置 IP、不修改路由 / 防火墙、不启动机器人服务。

## 有线直连

1. 用网线连接机器人和电脑，确认网口链路灯亮起，机器人正常开机。
2. 在终端运行 `./run.sh --interfaces`。找到实际有线网卡名称，例如 `enp3s0`；可用 `ip -br link` 和 `ip -br -4 addr` 交叉检查。
3. 查看机器人的网络文档或实际配置，确认机器人地址。`192.168.123.161` 是启动器默认检查目标，并不保证每台机器人都使用它。
4. 让电脑所选网卡处于相应 IPv4 网段，并使用未占用地址。**示例**：如果机器人是 `192.168.123.161/24`，电脑可配置一个确认未被其他设备占用的 `192.168.123.222/24`。不要把电脑地址也设为机器人的地址。

Ubuntu 桌面建议通过图形界面配置：

- **Settings → Network → Wired → 齿轮 → IPv4**（设置 → 网络 → 有线 → 连接设置 → IPv4）。
- 选择 **Manual**（手动），填入确认可用的电脑地址和网络掩码 `255.255.255.0`。
- 独立直连机器人时通常无需填写网关和 DNS；保留另一张 Wi-Fi 网卡用于上网即可。若使用实验室的路由网络，按该网络的实际规划填写。
- 点击 **Apply**（应用），重新启用该有线连接，然后再次查看 `ip -br -4 addr`。

若有网段冲突、已有设备占用示例地址或实验室使用其他地址规划，请先调整方案。地址是否空闲不能仅凭一次 ping 无响应判断。

```bash
ping -c 3 192.168.123.161
./run.sh --doctor --interface enp3s0
./run.sh --interface enp3s0
```

ping 成功只说明 ICMP 可达，不能证明 DDS 发现、组播、UDP 数据或相机服务可用。机器人可能禁用 ICMP，因此 ping 失败也不能单独判定 DDS 不可达。

## 自动网卡选择的含义

默认 `./run.sh` 根据 `--robot-ip`（默认 `192.168.123.161`）筛选接口启用、有载波、有 IPv4 的物理网卡，选择与目标同网段的唯一候选。多个候选会在交互终端显示选择菜单；无人值守或重定向输入时请显式提供 `--interface`。

自动选择不会给电脑分配 IPv4，也不会验证该 IP 就是 DDS 发布者。路由方案可能使用不同网段，此时请显式指定网卡，并由网络管理员确保 DDS 发现和数据通路可达。

```bash
./run.sh --interfaces --robot-ip 192.168.50.10
./run.sh --interface enp3s0 --robot-ip 192.168.50.10
```

同一网段存在多个机器人时，`--robot-ip` 不是话题来源过滤器。请隔离目标机器人网络，避免同名话题混合数据。

## Wi-Fi 与可路由网络

Wi-Fi 必须能到达机器人的实际 DDS 发布网络。电脑和机器人连接同一个热点并不保证该通路存在，尤其是机器人内部网段未桥接 / 未路由时。

AP 客户端隔离、禁止组播、VPN 路由、防火墙和 DDS domain 不一致都可能影响连接。先确认 IPv4 路由，再确认 DDS 发现及 UDP 数据流；不要为了排查直接关闭整台电脑的防火墙。

已建立合适网络通路时，可显式指定无线网卡：

```bash
./run.sh --interface wlp2s0 --robot-ip 192.168.123.161
```

在已确认路由和防火墙允许 DDS 的情况下，可增加 `--peer 192.168.123.161` 辅助单播发现；这不会建立路由或穿透防火墙。Wi-Fi、跨网段路由和断线重连尚未完成实机验收。

## 按层排查

| 现象 | 下一步检查 |
| --- | --- |
| `docker info` 失败 | Docker 是否安装 / 启动、当前用户是否有权限；可用 `sudo ./run.sh` |
| 首次镜像构建失败 | 基础镜像、Ubuntu 仓库及 GitHub 下载是否可达，查看构建日志 |
| 没有自动网卡候选 | 网线 / 载波、接口启用状态、IPv4 网段；运行 `--interfaces`，检查后显式指定网卡 |
| 浏览器无法打开 | 进程是否还在、地址与 `--port` 是否正确；后台查看 `docker logs g1-state-viewer-release` |
| 网页打开但所有通道等待 | 网卡、domain、发现通路、机器人是否发布这些话题 |
| 身体在线但点云等待 | 点云服务 / 话题名称 / QoS，不能据此认定整机未连接 |
| 已匹配但没有有效数据 | `/api/state` 中的 `matched`、`rejected` 和错误内容，消息结构 / QoS / 分片通路 |
| 视频显示结构或 ABI 错误 | 对照[兼容性说明](compatibility.md)，不必重启其他正常通道 |

只读话题发现：

```bash
./run.sh --discover --interface enp3s0 --seconds 8
```

先查 `rt/lowstate`，再查点云类型 `sensor_msgs::msg::dds_::PointCloud2_`。如果雷达使用其他话题：

```bash
./run.sh --interface enp3s0 --lidar-topic rt/实际话题
```

默认点云订阅使用 **reliable**，只能匹配 reliable 发布端。若发现发布端是 best-effort，改用 `--lidar-best-effort`，该接收方式也可匹配 reliable 发布端，但不要求重传。不要把画面频率当作传感器硬件的固定输出频率。

## 在另一台设备查看网页

```bash
./run.sh --interface enp3s0 --host 0.0.0.0
```

另一设备与运行查看器的电脑必须互相可达，浏览器输入 `http://电脑在该网络的IP:8765`。手机不需要直接连接机器人的 DDS 网段；DDS 接收仍由运行查看器的电脑完成。

HTTP 服务没有登录认证。仅在可信网络开放，按需限制防火墙来源，不做公网端口转发。默认 `127.0.0.1` 适合只在本机查看。
